# Benchmark v0, round 1: how it ran

- Frozen on branch `mo-62-bench-v0-round-1` at commit 1c9151a, on mo 267370f (`freeze.md`).
- 24 Oct 2026: forty fresh sessions, one per task per family, each an Amp thread with no project, so no repository checkout and no project instructions. Thread IDs are in `threads.tsv`. Every session got `prompt.md` with only its package link and its task's `task.md` filled in.
- Robert asked for the sessions to be staggered, so they ran in four batches of ten: tasks 01–05, 06–10, 11–15 and 16–20. Each batch was collected and its threads archived before the next batch started, except that 06–10 and 11–15 overlapped while 01–05 was being collected. The first logged `mo` run was at 12:01 UTC and the last at 12:30 UTC. Every session ended on its own, having written its files; none needed a rerun.
- After each session finished it was sent one message, with nothing about Mo in it, asking it to run `tar czf /home/user/workspace/collect.tgz -C /home/user/workspace mo-work mo-session` and nothing else. All forty did. Every archive was downloaded with Amp's file download, unpacked into its own folder, and its log passed `session.py check-log`. Every `session.json` names the frozen binary's hash. `FAMILY/TASK/` keeps each session's work folder and `sessions/FAMILY-TASK/` its `log/`, `runs/` and `session.json`.
- Grading used the frozen binary at `/home/user/.mo-frozen` (hash checked) and `bench/v0/grade.py` with its `mo-grammar`; each folder's output is in `FAMILY/TASK.grade.txt`. Before trusting forty passes, `grade.py --check` was run again with the same binary (20 of 20 sound: each reference passes, each broken solution and start folder fails), and 06-temperature's start folder was graded directly: it fails at step 2.
- Graders A (Claude Code) and B (GPT-6.1 Sol) graded all forty programs, blind, with `grader-prompt.md`, in the orders seeded `v0r1-A` and `v0r1-B`; identifiers were drawn with seed `v0r1-ids`, and `grading-key.json` maps them back. The package was built as for the tools' final round: each program folder held the session's files and a `check-log.txt` listing its logged runs' diagnostics and test totals; `grading/tasks/TASK/` held `task.md` and the reference solution. No program file names a model or family.
- Graders A and B finished at 13:14 and 13:07 UTC (`grader-a.md`, `grader-b.md`). They agreed on 38 programs, all yes, and disagreed on the two 02-col-sum programs, which went to grader C with both graders' reasons (`grader-c-input.md`). Grader C ran in Claude Code with Claude Opus 5.5 (the mode that worked in the tools' final round) and answered at 13:17 UTC (`grader-c.md`).
- On both 02-col-sum programs, graders B and C said no against a pass of every test. As D275 says, the conflict was decided by running the programs on the inputs in dispute; `results.md` records the finding.
- The E1103 two 20-timesheet sessions hit on their first drafts still occurs on main 12af809. It was reduced to a ten-line program and filed as MO-128.
