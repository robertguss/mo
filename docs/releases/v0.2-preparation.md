# v0.2 release preparation

**Unreleased. Phase 5 remains open.** These notes describe the development
implementation, not a released tag or a deployment. Final evidence and the frozen
build-input comparison are pending. Robert’s explicit approval is required before
any release. The [run record](../status/phase5-run.md) owns the evidence and limits;
[v0.1.0](../../README.md#install-v010-from-source) remains the released version.

## Implemented behavior

A service can accept a whole-program source upgrade at a message boundary.
Candidate checking verifies the old and new state types; pure migrations are
validated before durable activation. Checked restart offers a larger migration
budget, and offline rehearsal works over an exported snapshot with supplied source
and context artifacts. A successful activation records its committed ordinal;
rehearsal does not report one. `mo serve --data DIR` restarts the recorded program
without rerunning its committed migration.

The three MCP upgrade tools require both the service credential and a distinct
upgrade credential. The service token alone does not authorize upgrades, and
ordinary operator views remain read-only. All upgrade entry paths share the
implementation and report. Query diagnostics remain E1410–E1413; upgrade
diagnostics remain E1414–E1431.

`mo push` checks that its destination is loopback before reading either credential.
There is no TLS client in v0.2; remote operators use an SSH local forward. A raw
tunnel preserves Host, so local and remote ports must match unless the service
explicitly allows the forwarded authority. See the [runbook](../ops/task-queue.md#upgrade).
Only explicit no-effect rate refusals receive bounded, byte-identical retries.
The retry proxy control injects a synthetic refusal; it is not evidence of real
server bucket exhaustion.

No active-bundle read tool is included. MOSB source alone can omit historical
MOCC compilation context needed for rehearsal. Operators and evaluation sessions
must receive the required original source, bundle and context artifacts separately.

## Evidence still required

The final declaration is 1,000 seeded process kills, plus the observed stage
controls, reply/activation reconciliation and folder-only recovery. The declared
four-session agent evaluation must publish every session and miss, retain actual
client/model behavior including automatic fallback, and exclude development runs
from its denominator. A below-gate result leaves the phase open.

The production workload is 5,000 jobs with distinct 2,048-byte payloads and 500
leases. Final debug and optimized measurements must retain all repetitions,
stage metrics, host/storage disclosure and dispersion. The one-second target is
an engineering target; work budgets do not guarantee wall time.

A development identity transfer committed with a 0.540073616-second instrumented
debug pause, missing the declared twofold margin of at most 0.5 seconds. Live
post-push readback was interrupted; a separate recovery readback verified the
persisted jobs, payloads, attempts and lease deadlines. This is not a completed
final measurement series. The earlier job-reconstruction migration exhausted the
live work budget and was refused. Both outcomes remain in the
[measurement log](../../learnability/phase5/measurement-development.md).

library inputs, compiler commands and versions, binaries, protocol, clients,

## Retained limits

The compiler child shares the service’s identity, files and secrets; resource
limits are not OS isolation. Native work accounting does not bound allocator
internals, hash collisions, scheduling or disk synchronization. Candidate
initialization can stall service processing within its work bound, and a kill
during compilation can leave scratch directories. Shared rate limits permit
sustained upgrade starvation; checked restart remains the recovery path.

Parsing duplication remains. E1428’s deterministic reachability is not
established by this preparation. Process-kill observations do not establish
power-loss durability. A frozen client name does not pin provider model weights;
Claude’s recorded automatic fallback must not be described as an unchanged-model
result. Earlier failed assumptions and corrected evidence remain part of the
[preflight record](../../learnability/phase5/preflight/README.md).
