### 13.4 The `mo` command
Each command is given the file of the program's main module; `mo check` and `mo test` also accept a library module. `mo check FILE` reports the program's errors, `mo run FILE [ARGS...]` runs it with the arguments after the file's name, and `mo test FILE` checks its examples, promises and tests. `mo format` and `mo fix` rewrite the files they are given. `mo guide` needs no file. It prints a short guide for agents writing Mo, matched to the installed version: how to work with the `mo` command, a small complete program with its tests, and when a task is done. `mo guide --reference` prints this reference. `mo` exits with status 0 when everything passed, 1 when the program has errors or an example, promise or test fails, and 2 for a mistake in the command itself. Once the program runs, `mo run` exits with the program's own status (section 11.2), or 70 after a bug (section 13.2).
`mo test` runs every example, promise and test unless it's told which. Each has a full name: its function's name, or a test's module's, then its kind and a number counted from 1 in source order, such as `Wc.count.example.3` for the third example of `Wc.count`, `Account.transfer.promise.1`, or `Wc.test.2` for the second test in `Wc`. `--only NAME` runs the one with that full name, and can be given more than once; `--in MODULE` runs one module's, still checking the whole program; and `--list` prints the full names without running anything. A selection that matches nothing is a mistake in the command.
`mo run` and `mo test` limit what a program uses: `--max-stack` sets the bytes of stack, by default 8 MiB; `--max-depth` the calls in progress at once, by default 10,000; and `--max-heap` the bytes of memory, by default 1 GiB. Going past one is a bug whose report names the limit (section 13.2). A call in tail position takes its caller's place on the stack and doesn't count toward the depth (section 5.3). A program can't set its own limits.
`mo check --json` and `mo test --json` write one JSON object per line to standard output: first the format's version, then one for each error and for each example, promise and test run, and last the totals and the exit status. Within a major version of the format, every field keeps its name, type and meaning, and an error's code keeps its meaning; new fields and new kinds of object may be added, so a reader skips what it doesn't know. A message's wording may change.
## 14. The core library
Each function is listed under the type of its first parameter, written as it is called with a dot: under **Text**, `split(separator: Text) : List(Text)` is called as `text.split(",")`. A function written `Type.name(...)` is called through the type's module. `pred` is a function returning a `Bool`. Calling a function outside what it accepts, such as `take(-1)`, is a bug (section 13.2). Every type with the `Text` ability also has `to_text : Text`, its text form, and every type with `Order` has `compare(other: T) : Ordering` (section 9.2).
**Int**: `abs`, `min(b: Int)`, `max(b: Int)`, `pow(n: Int)` (`n` at least 0), `floor_div(b: Int)`, `floor_mod(b: Int)`, and `wrapping_add`, `wrapping_sub`, `wrapping_mul`, `saturating_add`, `saturating_sub` and `saturating_mul` (each taking `b: Int`), all `: Int`. `checked_add`, `checked_sub` and `checked_mul` `(b: Int) : Option(Int)`. `to_decimal : Decimal`, `to_float : Float` (rounded to the nearest float), `to_big : BigInt`, `to_byte : Option(Byte)`, `to_char : Option(Char)`, `to_text : Text`. `seconds`, `milliseconds`, `minutes`, `hours` and `days : Duration`.
**BigInt**: the arithmetic operators, `abs`, `min(b: BigInt)`, `max(b: BigInt)`, `pow(n: Int)`, `floor_div(b: BigInt)` and `floor_mod(b: BigInt)`, all `: BigInt`; `to_int : Option(Int)`, `to_text : Text`. **Byte**: `to_int : Int`, `to_text : Text`.
